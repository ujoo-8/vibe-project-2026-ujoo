[공지사항 게시판 생성 프롬프트]
-첨부: 게시판 각 화면(4가지), 
-프롬프트(원본):
아래 프롬프트를  검토 후 수정해줘. 이미 md지침은 완성되어 있어.
이 파일이 없어도 너는 아래 프롬프트를 요약적으로 간단히 수정 완성해.

첨부된 화면과 동일하게 공지사항 게시판을 만들거야.
DB없이 로컬스토리지로 개발할거야.
개발 후 파이어베이스 DB로 마이그레이션 할 예정이야.
따라서 localstorage_to_firebase_guidelines.md 파일 지침에 따라 개발 구현해야해.

위에 프롬프트와 이미지 4개를 첨부해서 얻은 내용.
-프롬프트(수정:클로드):
첨부된 4개 화면(목록 / 상세 / 글쓰기 / 글수정)과 동일한 UI로 공지사항 게시판을 개발해줘.

[개발 방식]
- DB 없이 localStorage로 구현한다.
- 개발 완료 후 Firebase(Firestore/Storage)로 마이그레이션할 예정이므로,
  반드시 localstorage_to_firebase_guidelines.md의 지침을 따라 구현한다.
  (지침과 충돌하는 부분이 있으면 지침을 우선한다.)
- 데이터 접근은 Repository(서비스) 계층으로 분리하고, UI에서 localStorage를
  직접 호출하지 않는다. 저장소만 교체하면 Firebase로 전환되도록 한다.

[화면 및 기능]
1. 목록: 총 건수(Total), 분류 필터(전체), 검색(제목 기준), 글쓰기 버튼,
   표(번호/제목/등록일/조회수), 최신순 정렬, 페이지네이션(페이지당 5건).
   등록 후 7일 이내 글에는 NEW 뱃지를 표시한다.
2. 상세: 제목, 등록일, 조회수, 공유하기(URL 복사), 본문(이미지 포함),
   이전글/다음글 이동, 목록으로 버튼. 진입 시 조회수 +1(새로고침 중복 방지).
3. 글쓰기: 제목(필수), 분류(공지사항), 내용(필수, 리치 에디터: 굵게/기울임/밑줄/
   정렬/링크/이미지), 첨부파일(10MB 이하, jpg/png/pdf), 취소/등록하기.
   필수값 미입력 시 검증 메시지를 표시한다.
4. 글수정: 글쓰기와 동일한 폼에 기존 데이터를 채우고, 수정하기 버튼으로 저장한다.
   삭제 기능은 상세 화면에 함께 제공한다.
5. 공통: 상단 공지 배너, 헤더(GNB), 푸터는 화면과 동일하게 구성한다.

[데이터 모델]
id, no, title, category, content(HTML), attachments[], views, createdAt, updatedAt
(Firebase 전환을 고려해 날짜는 ISO 문자열 또는 timestamp로 저장)

[제약]
- 첨부파일은 localStorage 용량 한계를 고려해 메타데이터(이름/크기/타입)만 저장하고,
  파일 저장 로직은 Firebase Storage로 교체 가능하게 인터페이스로 분리한다.
- 초기 샘플 데이터 7건(첨부 화면 기준)을 시드로 넣는다.
- 완료 후 변경 파일 목록과 Firebase 마이그레이션 시 교체할 지점을 요약해 알려준다.


[공지사항 만들기]
상단 맨위에 공지사항 한 줄 나오도록 배치해.
한 줄이지만 시간차를 두고 3개의 공지 제목이 돌게 만들어줘.
그리고 클릭을 하면 아래 페이지로 넘어가게 해줘.
첨부한 사이트 상단과 하단을 가지는 사이트의 공지사항(Notice) 게시판을 화면 중앙에 디자인해줘. 
공식 타이틀은 Notice야. 전체 디자인과 어울리는 색감, 글자, 배치를 고려해줘. 
가상 리스트를 7줄 정도 보여주고 페이징과 검색, 글쓰기버튼 등 기본적으로 필요한 게시판 형식을 갖춰줘.

리스트에서 클릭해서 나오는 글내용 보기 화면을 만들어.

[공지사항 구현 후 연계 수정하기]
- 공지사항 게시글 중 상위 3개 게시물을 별도의 박스로 구성하여 사이트 상단에 고정하고 한 줄 출력하기. 
내용은 3개의 게시물이 순서대로 넘어감 (멈춤, 플레이, 닫기버튼 포함)
